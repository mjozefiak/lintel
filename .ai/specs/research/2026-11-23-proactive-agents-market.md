# Proactive personal agents outside meeting tools — market scan (2026-11-23)

Scope: products that notice context on their own and propose an action the user approves. Dedicated meeting tools, Claude Meetings and the leaked "Parka" are covered in `2026-11-13-meeting-notes-market-B.md` and are not repeated here. Method: web search only, 2026-11-23. Labels: **FACT** (vendor page or several consistent reports), **INFERENCE** (my reading), **UNVERIFIED** (one weak source or conflicting sources). "acc." = accessed 2026-11-23 when the page shows no date. I did not open most pages in full; the search engine's summaries were the source, so treat quotes as paraphrase.

## 1. Big assistants

**ChatGPT Pulse → scheduled tasks.** Pulse launched 2025-09-25 for Pro on mobile: overnight research, then morning cards drawn from chats and, if opted in, Gmail and Calendar (e.g. a draft meeting agenda, a gift reminder) — FACT (https://techcrunch.com/2025/09/25/openai-launches-chatgpt-pulse-to-proactively-write-you-morning-briefs/, 2025-09-25; https://openai.com/index/introducing-chatgpt-pulse/). OpenAI's help page now says Pulse is being sunset and its updates move into scheduled tasks — FACT, no end date given (https://help.openai.com/en/articles/12293630-chatgpt-pulse, acc.). ChatGPT agent paused for confirmation before "high-impact" actions and offered "takeover" and "watch mode"; one help page now says agent is no longer available and points to "ChatGPT Work" — FACT for the confirmation design, UNVERIFIED for the retirement details (https://help.openai.com/en/articles/11752874-chatgpt-agent, acc.). INFERENCE: OpenAI tried an unprompted feed and fell back to user-scheduled prompts.

**Claude (Cowork).** Research preview 2026-01-12 on macOS, GA 2026-04-09 — FACT (https://www.techcrunch.com/2026/01/12/anthropics-new-cowork-tool-offers-claude-code-without-the-code/). Deletion always needs approval; an optional setting makes Claude show its plan and wait before anything significant — FACT (https://www.claude.com/product/cowork, acc.). It tries connectors first and only then drives the desktop — FACT (https://the-decoder.com/claude-code-and-cowork-now-let-anthropics-ai-take-control-of-your-mac-or-windows-desktop/, acc.). Scheduled tasks run a saved prompt on a cadence, now in the cloud, locally only if they need local files — FACT (https://support.claude.com/en/articles/13854387-schedule-recurring-tasks-in-cowork, acc.). Support pages say "Claude Cowork is now just Claude" for Pro/Max — FACT (same page). I found **no** unprompted, event-triggered proposal mode. "Duet": nothing found. Proactivity in Anthropic's line is Parka-style action items routed to Cowork (see earlier doc) — rumoured.

**Google Gemini.** Daily Brief (I/O, 2026-05-19): opt-in morning digest from Gmail, Calendar and Gemini chats, with a "Top of mind" list of actionable items — FACT (https://techcrunch.com/2026/05/19/google-updates-its-gemini-app-to-take-on-chatgpt-and-claude-at-io-2026/; https://support.google.com/gemini/answer/17077455, acc.). Free in the US since September 2026 — FACT (https://9to5google.com/2026/09/08/gemini-daily-brief-free/, 2026-09-08). Gemini Spark: a "24/7" agent "under your direction", Ultra first, Mac app integration announced for later — FACT as announced, shipping state UNVERIFIED (https://blog.google/innovation-and-ai/products/gemini-app/next-evolution-gemini-app/, acc.). Android "Gemini Intelligence" does multi-step app tasks and "only acts on your command" — FACT (https://blog.google/products-and-platforms/platforms/android/gemini-intelligence/, 2026-05-12). An unreleased "Proactive Assistance" uses screen, notifications and allowed apps, processed on-device per in-app text — UNVERIFIED teardown (https://androidauthority.com/google-gemini-proactive-assistance-3661314, acc.).

**Apple Intelligence / Siri AI.** Siri AI with personal context, on-screen awareness (Mac: a keyboard shortcut) and actions, beta in English from September 2026, then French, Japanese, Korean, Portuguese, Spanish — FACT (https://www.apple.com/newsroom/2026/09/siri-ai-a-profoundly-more-capable-and-personal-assistant-is-here/, 2026-09). **Microsoft.** Click to Do (over Recall snapshots, Copilot+ PCs, 40 TOPS NPU, 16 GB): user selects on-screen text/image and picks an action (send email, open with, Phi Silica text actions, English only); some actions send content online — FACT (https://support.microsoft.com/en-us/windows/click-to-do-in-recall-do-more-with-what-s-on-your-screen-967304a8-32d1-4812-a904-fad59b5e6abf, acc.). YC-backed — secondary. **Khoj:** self-hostable assistant with scheduled automations — FACT (repo summary, acc.). **Open Interpreter:** 01 hardware dropped; commercial desktop app by Open Interpreter Inc., freemium — UNVERIFIED secondary (https://aiwiki.ai/wiki/open_interpreter, acc.). ## 5. How a local macOS app can execute actions with approval

| Channel | Mechanism | Permission / privacy | Risk notes |
|---|---|---|---|
| **Calendar** | EventKit. `requestWriteOnlyAccessToEvents` + `NSCalendarsWriteOnlyAccessUsageDescription`; full access only if reading for conflicts. Apple: don't ask for full access if write-only suffices — FACT (https://developer.apple.com/documentation/eventkit/accessing-the-event-store, acc.). Or `EKEventEditViewController`-style editor so the user saves. | Uses whatever accounts the user has in Calendar.app (Google, Exchange, iCloud); no OAuth; nothing leaves the Mac. macOS-specific write-only behaviour UNVERIFIED. | Lowest-risk first action. |
| **Mail** | (a) `mailto:` with subject/body → user's client, user presses Send. (b) AppleScript to Mail.app to create a visible draft: needs `com.apple.security.automation.apple-events` + `NSAppleEventsUsageDescription`, TCC "Automation" prompt — FACT (https://developer.apple.com/forums/thread/750802, acc.). (c) Gmail API: `gmail.compose` is **restricted** (verification, annual CASA if data reaches servers); `gmail.send` is sensitive, no assessment — FACT (https://developers.google.com/identity/protocols/oauth2/production-readiness/restricted-scope-verification, acc.). | (a) zero permissions; (b) Automation grant covers all of Mail's scripting (read too) — INFERENCE; (c) Google verification weeks; local-only CASA exemption not settled. | Never auto-send. Wispr is blocked on exactly (c). |
| **Jira** | REST v3 with the user's API token (Basic). Scoped tokens must go via `api.atlassian.com/ex/jira/{cloudId}`; tokens max 1 year — UNVERIFIED community/secondary (https://support.atlassian.com/atlassian-account/docs/manage-api-tokens-for-your-atlassian-account/, acc.). Or OAuth 3LO (needs an Atlassian app). | Token in Keychain; token carries the user's full rights. Sends issue text to Atlassian (expected). | Show the exact fields before create. |
| **Linear** | GraphQL `issueCreate`, personal API key in `Authorization` header, or OAuth2 — FACT (https://linear.app/developers/graphql, acc.). | Key = creator's permissions. | Same. |
| **MCP client** | Lintel calls the user's MCP servers (Atlassian Rovo MCP, GitHub, etc.). `destructiveHint` defaults to true; annotations are untrusted hints; few clients surface them in approval prompts; elicitation lets a server ask the user — FACT (https://blog.modelcontextprotocol.io/posts/2026-03-16-tool-annotations/, 2026-03-16). An arXiv paper finds neither servers nor hosts reliably confirm destructive tools — title-level FACT (https://arxiv.org/pdf/2611.02527). | Broadest reach, weakest guarantees; local stdio servers run arbitrary code. | Host-side confirmation of **every** write is on Lintel. |
| **Shortcuts / App Intents** | `shortcuts run "<name>"` with stdin input; prompts inside a shortcut block the CLI — FACT (https://support.apple.com/guide/shortcuts-mac/apd455c82f02/mac, acc.). Expose Lintel's own App Intents so Siri/Shortcuts can call Lintel. | User builds the shortcut, so they own the integration; first-run prompt per shortcut (UNVERIFIED). | Good escape hatch for anything Lintel doesn't integrate. |

Cross-cutting: transcripts include **external speakers**, so a meeting is an untrusted input like Comet's calendar invite. INFERENCE: proposals must be data (a typed action with fields), the model never holds credentials, and nothing writes without a click.

## 6. Positioning gaps Lintel could own

1. **Speech as the trigger.** Everyone else triggers on inbox, calendar or screen (Pulse, Daily Brief, Littlebird, Highlight, Superhuman). Proposals from what was *said* in a meeting or dictated note, without a bot, exist only as Parka (rumoured, cloud) and DIY Screenpipe pipes. INFERENCE.
2. **On-device detection, explicit egress.** Detection runs locally; data leaves only on approval and only to the one target (Jira, Calendar). No competitor above combines local detection with action proposals (Gemini's Proactive Assistance claims on-device but is unreleased, Android). INFERENCE.
3. **Approval as a reviewable card, not chat.** Show the exact Jira fields / event time / email body, editable, with the transcript quote that triggered it. MCP clients rarely surface tool risk in prompts (MCP blog). INFERENCE.
4. **Polish and mixed PL/EN.** Siri AI, Click to Do intelligent actions and many brief features are English-first; Polish missing from Apple's list. FACT for Apple/Microsoft; opportunity INFERENCE.
5. **Narrowest permissions.** Write-only calendar, `mailto`/Mail draft by default, user-held Jira/Linear tokens in Keychain, no Google restricted scope needed. Wispr shows the Gmail-review trap. INFERENCE.
6. **Don't compete on daily briefs.** Briefings are now free (Gemini) or folded into scheduled tasks (OpenAI). INFERENCE.
